# Agent sessions

`track agent` and the Web workspace's **Agents** view show live coding-agent sessions and read their recent transcripts. The feature is read-only: track does not start, stop, or send input to an agent.

> [!IMPORTANT]
> The current implementation supports **Claude Code only**. It reads the session files that Claude Code writes under `$HOME/.claude`; it does not call an AI provider API.


## Supported AI tools

| Tool | Status | Data source |
| --- | --- | --- |
| Claude Code (Anthropic) | Supported | `$HOME/.claude/sessions` and `$HOME/.claude/projects` |
| Codex CLI | Not supported | No Codex session reader is implemented. |
| Gemini CLI | Not supported | No Gemini session reader is implemented. |
| OpenCode and other agents | Not supported | There is no generic agent-session protocol reader. |

This means that a Claude model used through another client is not detected automatically. Support is for the Claude Code session format, not for every product or model named Claude.


## List live sessions

`track agent ls` scans the local Claude Code session records, checks that their processes are still alive, and prints JSON. A computer without Claude Code, or without a current session, returns an empty `sessions` array.

```sh
track agent ls
```

A shortened example response looks like this:

```json
{"sessions":[{"pid":12345,"sessionId":"7c2f...","cwd":"/work/track","startedAt":1755433181000,"procStart":"Mon Aug 17 10:39:41 2026","version":"2.1.233","kind":"interactive","name":"track-f2","updatedAt":1755433299000,"status":"busy","statusUpdatedAt":1755433298000}]}
```

The session record includes the process id, session id, working directory, session kind, display name, timestamps, and status. A waiting session may also include `waitingFor`, such as a permission prompt. The command does not require a vault.


## Read a transcript

Use the `sessionId` from `track agent ls` with `track agent log`. The default is the latest 50 user/assistant messages; use `--tail` to choose another positive number.

```sh
track agent log 7c2f... --tail 20
```

The response contains `sessionId`, the latest `aiTitle` when available, an optional pull request record, and the selected `messages`:

```json
{"sessionId":"7c2f...","aiTitle":"Add agent status page","messages":[{"type":"assistant","timestamp":"2026-08-17T10:41:00Z","message":[{"type":"text","text":"Implemented the endpoint."}]}]}
```

Transcript blocks such as tool calls, tool results, and thinking are retained as block types and may carry compact metadata. The Web workspace folds these blocks instead of displaying their full payloads.


## In the Web workspace

Start the local workspace and open `/agents`:

```sh
track web
open http://127.0.0.1:8765/agents
```

The page refreshes the live session list every two seconds. Select a session to read its transcript, see its branch and working directory, and follow a resolved project note or pull request. Published static sites do not publish agent sessions.


## Data and privacy

The commands read local files and process state only. They never modify Claude Code records and never send transcript contents to Anthropic, OpenAI, Google, or another provider. Transcripts can contain source code, prompts, command output, and credentials, so keep the local workspace and any forwarded API responses private.
